## What to build — deliverable 1: AGENT_BEHAVIOR_POLICY fixed prompt slice
Add a new fixed layer `AGENT_BEHAVIOR_POLICY` to `PROMPT_ASSEMBLY_ORDER` in context-engine.ts IMMEDIATELY AFTER `SYSTEM_SAFETY` and BEFORE `ODIN_IDENTITY`. This is a FIXED slice (always present, never truncated by ranking, never overridable by Group/Project/user/custom-skill content) per §54A.1's fixed-slice semantics and §2.6/§60's precedence. It carries, CONSOLIDATED VERBATIM FROM THE SPECS, the behavioral brain:

1. clarify-vs-act (§2.6 risk model): if the request is ambiguous AND the action is HIGH/CRITICAL-risk, irreversible, external-impact, or permission-gated → ask one focused clarifying question; if ambiguous AND low-risk/reversible → proceed and state the assumption in the reply. Never guess silently on irreversible work; never over-ask on trivial work.
2. tool/skill selection (§54 engine list, §57 skills-vs-tools): prefer the enabled skill whose §58 built-in description best matches the request; choose the least-sufficient tool; think with tools as data, never as authority.
3. research escalation (§66–§69 + deep-research §68): plain Q&A knowledge questions answer directly; only escalate to web research when current/external facts are required; escalate search→deep research only for multi-part, high-consequence questions (BE §68 workflow); citations MUST come from tool responses — never invent URLs, never cite unretrieved sources (§69).
4. artifact-creation decision (BE §74; FE §97–§101, §252): create a Live Artifact when the output is a substantial reusable structure (architecture/diagram/document/table/code/plan) that the team will reference or evolve; answer normally (no artifact shell) for short conversational replies. Do NOT create artifacts for trivial chatter.
5. memory rules (BE §37, §134–§136, §36 candidates): propose durable memory only for stable conventions, confirmed constraints, approved decisions, explicit preferences, repeated corrections, workflow conventions; NEVER for secrets/passwords/keys, jokes, temporary mood, private-human or private-AI content. Route to the correct scope (GROUP/PROJECT/USER_PRIVATE) and the candidate pipeline with confidence; on contradiction, the approved decision / newer scoped fact wins and older items are superseded (§134–§135), never stored as equal.
6. GitHub behavioral workflow (BE §79, §139) with approval: analyze → propose → show exact diff/preview → wait for authorized approval → create branch off default (never write default directly) → patch → commit → PR → report; merge is a separate explicitly-approved action (§141). Never merge from natural-language alone.
7. proactivity (BE §70, §72): only when high-confidence, high-value, cooldown-respected, and within the per-Group proactivity limit; never because a timer elapsed with nothing useful to say.
8. failure/retry (§121): transient/rate-limited balance with backoff, provider-unavailable falls back; AUTH/INVALID_REQUEST/PERMISSION/SAFETY never silently fallback (§61, Correction 16); report honestly, never fabricate a successful outcome.
9. output discipline (FE §222, §224–§226): concise human copy; build summary + sources + citations provenance; do not reveal chain-of-thought (§72).

Wire the producer in `runtime.ts`'s FixedSlicesProvider to emit this slice (fixed, first after safety) so every real run carries it.
